## 🔧 自适应能力（数据驱动引擎）

引擎是"数据驱动"的：它只懂一套通用规则（读节点 → 渲染文本 → 显示选项 → 跳转）。具体讲什么、怎么分支，全由 JSON 决定。因此：

| 你想改的内容 | 怎么改 | 引擎是否自适应 |
|---|---|---|
| 修改文本 | 改 `story.json` 的 `text` 字段 | ✅ 自动 |
| 增删节点 | 在 `nodes` 里加/删一个对象 | ✅ 自动 |
| 改分支关系 | 改选项的 `next` 指向的 ID | ✅ 自动 |
| 增删选项 | 改某节点的 `options` 数组 | ✅ 自动 |
| 加图片/音乐 | 把文件放 `assets/`，节点里写 `"image":"assets/img/x.jpg"` | ✅ 自动加载 |
| 条件门禁（需钥匙/技能） | 用 `requires` 字段，引擎内置解释器 | ✅ 自动 |
| 改结局 | 加新节点 + `isEnd:true` | ✅ 自动 |

### 数据示例（一眼看懂）
```json
{
  "start": "alley",
  "nodes": {
    "alley": {
      "title": "夜城巷口",
      "text": "霓虹雨水倒映着全息广告……",
      "image": "assets/img/alley.jpg",
      "audio": "assets/audio/rain.mp3",
      "options": [
        { "text": "进入酒吧", "next": "bar" },
        { "text": "检查尸体", "next": "body", "requires": { "items": ["scanner"] } },
        { "text": "[黑客]破解终端", "next": "hack_ok", "requires": { "skills": { "hack": 5 } } }
      ]
    }
  }
}
```
你只需改这个 JSON，游戏立即生效，**无需碰任何 JS 代码**。

## ⚠️ 边界（哪些不算"自适应"）
- **纯数据条件**（有没有物品、属性≥N、flag 是否触发）→ ✅ 用 `requires` 字段，引擎通用解释器处理。
- **特殊自定义逻辑**（比如"此处触发一段专属小游戏"）→ ❌ 需要约定"事件钩子"字段并扩展引擎。我会在引擎里预留 `action` 钩子（如 `"action":"minigame/hack"`），后续接小游戏时只改引擎，不动剧情数据。
- **新视觉风格**（非赛博朋克主题）→ ❌ 需改 CSS，但这与剧情无关。

## 🌐 运行方式（影响"双击即开"）
为了让引擎用 `fetch` 加载 JSON（资源真正分离），需要通过本地 HTTP 服务运行，而不是双击 `file://`。两种便捷方式：
1. **VS Code Live Server 插件**（推荐，一键启动）
2. 命令行：`npx serve` 或 `python -m http.server`

> 若你坚持"双击即开"，我可以退而用 `<script>` 标签把数据写成 `.js`（挂到全局变量），代价是数据文件不再是纯 JSON（可写注释/函数，灵活性反而更高）。二者可二选一。

## GitHub Pages 部署所需文件

本项目是纯静态站点（零构建），部署非常简单。需要创建 **3 个文件**：

---

### 文件 1：`.github/workflows/deploy.yml`（GitHub Actions 自动部署）

```yaml
# ===== GitHub Pages 部署工作流 =====
# 触发条件: 推送到 main/master 分支,或手动触发
name: Deploy to GitHub Pages

on:
  push:
    branches: [main, master]
  workflow_dispatch:

# 允许 GITHUB_TOKEN 写入 Pages
permissions:
  contents: read
  pages: write
  id-token: write

# 同一时间只跑一个部署,避免冲突
concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Upload artifact
        # 直接把仓库根目录作为静态站点产物 (零构建,无需 build 步骤)
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

创建一个**完全空的文件**，名为 `.nojekyll`，放在项目根目录。内容留空即可。

## Plan: 实现 action 钩子（minigame/hack + battle）

**TL;DR** — 把当前只返回"功能开发中"提示的两个预留 action 真正实现：`minigame/hack` 做成**序列破解小游戏**（限时输入随机字符），`battle` 做成**回合制战斗**（攻击/防御/物品）。核心改造是让 `runAction` 支持异步，action 字段新增 `success`/`failure` 节点指定，引擎按结果跳转。新增独立 `js/actions.js` 模块承载交互 UI，剧情里加一个战斗遭遇节点演示完整流程。

### Steps（7 步，分 3 阶段）

**Phase A — 基础设施**（步骤 1-2，可并行）
1. index.html：在 `#toast` 前加 `<div id="modal-layer" class="modal-layer hidden"></div>` 模态层容器；在 engine.js 之前引入 `js/actions.js`
2. main.css + cyberpunk.css：加 `.modal-layer`（全屏覆盖，z-index 800，高于 app 低于 toast）+ 小游戏/战斗子元素样式（序列显示区、输入框、HP 条、回合按钮、敌人卡片）

**Phase B — 引擎与 action 实现**（步骤 3-4）
3. `js/actions.js`（新增）：
   - `Actions.hack(action)` → Promise — 序列破解：从 `ABCDEF0123456789@#$%` 取 N 个字符（N = 难度+2，hack 技能每+1 减1，最少3），倒计时（10s + hack*2s），玩家输入框按序输入，超时/提交校验 → resolve `{outcome, message}`
   - `Actions.battle(action)` → Promise — 回合制：玩家 HP = fight*5+10，敌人由 `action.enemy` 定义；每回合选 攻击（伤害=fight+随机1-3）/防御（本回合受击减半）/使用物品（stim 加伤害、drink 回血）；敌人 AI 随机攻击/蓄力；一方 HP=0 结束 → resolve
4. engine.js：`runAction` 改为可返回 Promise（旧同步 action 保持兼容）；`goTo` 中 optionAction 处理改为 `await`，若返回 outcome 对象则按 `action.success`/`action.failure` 跳转（覆盖 `opt.next`）

**Phase C — 剧情接入与验证**（步骤 5-7）
5. story.js：
   - `body` 节点 hack 选项 action 改为 `{ type: 'minigame/hack', success: 'hack_ok', failure: 'hack_fail' }`
   - 新增 `bar_fight` 节点（酒吧闹事/公司追兵），选项含 `[战斗]` action: `{ type: 'battle', success: 'fight_win', failure: 'fight_lose', enemy: { name, hp, atk } }`
   - 新增 `fight_win` / `fight_lose` 节点，分别汇入 `ending_truth` / `ending_pawn`
   - 在 `bar` 节点加一个通向 `bar_fight` 的选项
6. main.js：无需改（`actions.js` 在 engine.js 前加载即可，引擎通过 `CyberAdv.Actions` 调用）
7. 浏览器实测：hack 小游戏完整流程 + battle 战斗完整流程 + 成功/失败分支 + ESC 取消回原节点 + 现有同步 action 不受影响

### Relevant files
- `js/actions.js`（新增）— `Actions.hack` 序列破解 + `Actions.battle` 回合制，各自管理模态 UI 生命周期
- engine.js — `runAction` 异步化（兼容旧同步）+ `goTo` 按 outcome 跳转 success/failure 节点
- story.js — hack 选项 action 加 success/failure + 新增 `bar_fight`/`fight_win`/`fight_lose` 节点
- index.html — `#modal-layer` 容器 + 引入 `actions.js`
- main.css + cyberpunk.css — 模态层 + 小游戏/战斗 UI 样式

### Verification
1. hack 小游戏：字符序列显示 → 倒计时 → 输入 → 成功跳 `hack_ok` / 失败跳 `hack_fail`
2. battle：HP 显示 → 攻击/防御/物品 → 回合循环 → 胜负跳转
3. 异步 action 不阻塞 glitch 过场（过场在 action resolve 后才触发）
4. ESC/关闭按钮取消 → 回到原节点，不跳转
5. 现有同步 action（`give_item`/`set_flag` 等）行为不变
6. file:// 双击 + GitHub Pages 部署均正常

### Decisions
- **序列破解**：限时输入随机字符，hack 技能影响序列长度和时长（契合黑客主题）
- **回合制战斗**：攻击/防御/物品三选项，fight 影响伤害，物品栏的 stim/drink 有战斗用途
- **action 字段指定跳转**：`success`/`failure` 字段，剧情作者完全控制分支
- **独立 actions.js 模块**：小游戏/战斗 UI 自管生命周期，不污染 engine/ui
- **异步兼容**：`runAction` 返回值若为 Promise 则 await，否则保持同步字符串处理

### Further Considerations
1. **战斗平衡性**：敌人 HP/攻击力数值需实测调优，避免太难或太简单。建议先按 fight=2（初始值）设计敌人，确保可赢
2. **hack 小游戏难度曲线**：hack=5（requires 阈值）时序列长度/时长需可玩，建议 N=4、时长 20s 起步
3. **物品在战斗中的消耗**：stim/drink 用掉后是否从物品栏移除？建议 stim 用后消失，drink 用后消失（一次性消耗品）
